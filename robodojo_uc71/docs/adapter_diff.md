# UC7.1 native ARX model/plan adaptation

Status: offline client/schema implementation only. The native RTX smoke failed during Hydra initialization before a first frame. Simulator integration, actual RGB/calibration, controller timing and task execution are **unvalidated**. No preview, approval or successful native task is implied by these files or their mocked tests.

## Frozen reuse

The adapter imports `vendor/uc71/src/gpt_field` and rejects an already loaded shared-tree package. No frozen source is modified. `NativeExecutiveClient` inherits the frozen accepted-history commit, chronological text and opaque reasoning replay, bounded same-observation transport retries and usage accounting. The frozen image trimming function retains six whole image-bearing turns, now three images each. The production transport remains subscription OAuth, high reasoning, streaming progress and a 180-second per-send deadline; requests require the parent main thread. Construction and payload builders are offline.

`TaskContract`, direction-frame construction/validation and plan semantic validation remain frozen dependencies. The local lock does not instantiate Panda scene/macro objects. The planning schema adds `r` to each part: `x` means head grid (image 2), `w` left wrist grid (image 4), and `r` right wrist grid (image 6). Each cell is 0..64, with 0 meaning not visible. Removing only `r` produces a losslessly validated frozen plan. Original semantically invalid drafts are retained; approval must call `validate_plan(..., semantic=True)`.

## Explicit pilot differences

- Two ARX arms; exactly one selected `arm_id` per execute/motion decision. Every segment in that decision uses that arm. Observe/finish use null. This is not simultaneous two-arm trajectory generation.
- Five generic fragment skills remain: move_to_pose, move_relative, approach, set_gripper and wait. Short direct motion, observe and finish remain. The controller/runner must implement their measured feedback and interruption semantics; schema tests do not demonstrate physical execution.
- Panda native macros hold/turn/place_on/release and their calibration/registration/held-object observers are unavailable. Macro action selection is removed from the executable schema and macro prompt block. The capability block explicitly reports the reduction. This follows the reviewed zero-use evidence, but it is still a capability reduction, not byte-identical policy parity.
- Images are native, unflipped, unrotated 640x480 RGB. Initial planning receives three clean images and three 8x8 grid overlays. No numeric robot state, calibration, direction frame or execution evidence enters initial planning. Execution receives three clean images, both arms' measured robot state and camera/fixed-tool calibration. The first executive observation preserves starting robot poses in text history.
- The official task sentence remains unchanged. Both prompts additionally disclose this public, task-agnostic rule: “A task counts as complete only when both arms are back at the pose they started the episode in.” No numeric homing thresholds, recipe, automatic retreat or homing controller is added.
- Camera calibration uses optical +X right, +Y down, +Z forward. The unchanged direction-frame function receives an explicit optical-to-OpenGL basis conversion, without transforming the delivered RGB. The reviewed head-camera frame is repeated every executive request, including when there are no directional regions.
- Each arm exposes six measured joint positions/velocities, two actual measured finger positions and measured tool pose xyz+wxyz. `finger_gap_m` is their sum and is explicitly a joint-separation proxy, not inner-pad clearance. Commanded binary gripper state is separate. Full robot URDF/meshes/joint limits and scene truth are excluded from model calibration.
- Candidate 25 Hz fragment limits preserve former durations: 150 actions per segment (6 s), 300 per execution (12 s), gripper minima 10 open/15 close (0.4/0.6 s). Direct motion intentionally keeps 1..5 native actions (0.04..0.20 s). Target envelopes remain 0.30 m/1.2 rad transit, 0.08 m/0.5 rad contact, 0.05 m/0.35 rad direct. These are **uncalibrated candidate limits**, requiring measured characterization and freezing before a pilot.
- Robot feedback uses a small typed schema with enumerated status/reason codes and at most 32 robot measurement samples, instead of arbitrary native-macro evidence and its 45,000-character compaction path. The 56,000-character current-request ceiling is retained. Excess/unknown fields are rejected, not truncated. Full controller traces remain runner audit artifacts. No native remaining-budget or reward channel is supplied.

## Runner-facing API

`NativePlanClient(task_prompt=..., token_provider=..., log_dir=...)` exposes `planning_request(images)` and `request_plan(images)`. `images` has exactly `head`, `left_wrist`, `right_wrist`; values are uint8 RGB arrays, RGB PNG bytes or inline PNG data URLs. No HTTP image URLs are accepted. The pilot uses zero wrist quarter turns.

`NativeExecutiveClient(task_prompt=..., approved_plan=..., direction_frame=..., token_provider=..., log_dir=..., limits=ExecutionLimits(), controller_capabilities={})` exposes offline `agent_request(observation, feedback=None, execution=None)` and live `request_agent(...)`. The parent owns approval and launch; the client never claims a review or starts a simulator.

Observation keys are exactly `step`, `images`, `robot`, `calibration`, optionally `direction_frame`. `step` must equal the number of accepted model decisions, beginning at zero; native action counts are prohibited. Robot entries `left`/`right` contain `tool_pose_wxyz[7]`, `joint_position_rad[6]`, `joint_velocity_rad_s[6]`, `finger_position_m[2]`, `finger_gap_m`, and `gripper_command` (`open`/`close`).

Calibration version `robodojo-uc71-calibration-1` contains three cameras (`width`, `height`, `intrinsics[3,3]`, `world_from_optical[4,4]`, `pose_source`) and two tools (`link_name='link6'`, `link6_from_tool[4,4]`, `finger_gap_formula='sum_of_measured_finger_joint_positions'`, `finger_gap_semantics='joint_separation_proxy'`, `source_sha256`). Use `direction_frame_from_calibration()` for the review frame. Tool provenance is fixed during the attempt.

Decisions contain exactly `belief`, `plan`, `why`, `type`, `arm_id`, `motion`, `execution`. Inactive payloads are null. Validation catches malformed later segments before the runner executes any of them. Absolute target bounds require measured entry-state enforcement by the controller; this layer cannot certify reachability, contact, support, grasp or success.

Feedback is strictly allowlisted robot/controller evidence: required `status` and enumerated `reason`; optional `arm_id`, `skill`, local `executed_steps`, `gripper_command`, position/orientation errors, measured finger proxy, entry/target/last tool poses, completed/pending segment indices, and at most 32 typed robot measurements. Unknown keys, arbitrary reason prose, raw exceptions and debug dictionaries are rejected, including inside samples. `execution`, when provided, has exactly `decision` (equal to the prior accepted model decision) and `progress` (typed feedback or null). Controller capabilities accept only the versioned controller status, explicit positive scalar limits/sample counts, and transit/contact motion/tolerance maps; no arbitrary metadata. Camera dimensions, intrinsics, source labels, head extrinsic and tool provenance remain fixed; only synchronized wrist extrinsics may change. Source separation is still required: the runner must never populate even an allowed measurement channel from evaluator truth.
