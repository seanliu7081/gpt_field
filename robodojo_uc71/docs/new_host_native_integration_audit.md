# Native integration audit for the new host

Read-only source investigation recorded on 2026-10-29. This document is the only file created by this audit. No simulator, policy model, native action, installation, checkout or asset download was performed. The new-host procedural camera gate was still pending when this was written; none of the findings below establish a runtime pass.

Sources were inspected through the GitHub connector at native commit [`f57e1633ffed59761bc8e568cfe7530c4b33381c`](https://github.com/RoboDojo-Benchmark/RoboDojo/tree/f57e1633ffed59761bc8e568cfe7530c4b33381c). The intended pilot remains Make Toast **Standard, seed directory 0 / layout ID 0**, one environment, dual ARX arms, three native 640×480 views, Astra high through subscription transport and a 1,400-native-action horizon. Full-test approval remains absent.

## Current adapter boundary

The local adapter implements schemas, subscription client wrappers, planning helpers, dedicated Unix-socket IPC, single-use approval primitives, action accounting and an uncalibrated differential controller. It does not yet provide a native simulator worker, fragment executor, calibrated robot/camera integration or full-attempt runner.

The frozen `vendor/uc71` core and historical provisioning evidence must remain unchanged. Native source and assets belong under an isolated runtime location after the camera gate; do not run the upstream installation/evaluation shell scripts unchanged.

## Native APIs and integration requirements

1. **Configuration.** Follow the assembly in [`src/eval_client/main.py`, `main()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/src/eval_client/main.py#L254). Relevant imports are `OmegaConf` from `omegaconf`, `load_yaml` from `utils.load_file`, and `process_config` / `process_randomization` from `utils.pipeline_utils`. Load `env_cfg/arx_x5.yml`, its selected simulator/scene/robot/camera YAMLs, and `task/RoboDojo/config/make_toast.yml`. Set one environment, seed directory 0, and `camera.default_frequency=25`. Preserve native `dt=0.004`, `render_interval=10` and decimation 1. [`process_config`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/utils/pipeline_utils.py#L76) applies Make Toast's `data_source: teleop` stabilization and `robot_self_collision: false`; these physics settings are required even though no demonstrations are consumed.

2. **Startup and monitoring.** Native startup imports `AppLauncher` from `isaaclab.app`, starts `get_monitor()` from `src.eval_client.physx_warning_monitor` before Kit redirects/inherits stdout/stderr, then applies `add_zero_delay_kit_args` from `env.camera_manager.capture.render_sync`. See [startup ordering](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/src/eval_client/main.py#L111). Make Toast contains an articulation and therefore enables this monitor. Preserve monitoring but turn fatal/broken state into a terminal infrastructure error; do not invoke upstream shell or process restarts. IPC must remain on its dedicated inherited socket.

3. **One environment without upstream policy transport.** Import `create_eval_env` from [`src.eval_client.eval_env`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/src/eval_client/eval_env.py#L43). It dynamically subclasses the registered native task, constructs `WsModelClient` unconditionally and sends a client `reset` call during environment reset. A narrowly scoped, reviewed adapter replacement can allow only this reset notification and reject inference/network calls. The native module imports `WsModelClient` from `client_server.ws.model_client`, so the pinned XPolicyLab import path remains a dependency. Do not execute upstream `main.py`, `run_eval()`, resume handling or policy episode loops to prepare this adapter.

4. **Exact layout and native reset.** [`SeedManager.init_eval()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/seed_manager/seed_manager.py#L28) enumerates matching layout filenames in numeric suffix order. Verify `seed_info[0]` resolves to the exact selected file and SHA-256 in `configs/source_pins.json`, then call `env.reset(seed=[0])` once. [`TaskEnv.reset()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/environment/task_env.py#L85) includes 300 settling steps. [`EvalEnv.reset()` / `setup_scene()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/src/eval_client/eval_env.py#L208) additionally apply saved poses, check layout stability, render ten times and execute 200 preparation steps, then set origin/init robot state and initialize rewards. Preparation steps are separately recorded from policy actions. Reject instability or identity mismatch; do not substitute a layout or retry automatically.

5. **Reward registration and terminal truth.** [`run_eval()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/src/eval_client/eval_env.py#L771) normally calls `env.run_reward()` and `env.get_score()` before policy execution. A custom worker bypassing `run_eval()` must preserve those registrations explicitly. `success` initializes to `True`, so it is not success evidence. [`take_action()` / `take_action_batch()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/src/eval_client/eval_env.py#L354) perform native joint/gripper mapping, ten-step interpolation, physics, `reward_manager.step()` and `is_episode_end()`. Bind the actual registered callback's reward/end result to `EpisodeLifecycle`; do not infer success from process exit, model `finish` or initial flags. Preserve the hard stop before action 1401.

6. **Robot-only joint control.** Use native joint-action keys `left_arm_joint_state`, `left_ee_joint_state`, `right_arm_joint_state`, and `right_ee_joint_state`. Read six measured arm positions/velocities and both physical finger joints from each `robot_manager.robot_key` articulation. [`RobotManager._setup_robot_key()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/robot_manager/robot_manager.py#L493) resolves actual joint indices. `get_link_pose()` reads `data.body_link_pose_w`; `get_end_effector_real_val()` reads measured finger joints. Native scalar gripper state in `ObsManager` is the previous command, not a physical measurement. Validate fixed-base Jacobian body indexing, joint ordering, world-frame convention, live limits, TCP offset and finger-gap semantics against the rendered robot before controller use. The local `ControllerConfig.validate()` currently only accepts `uncalibrated_candidate`; a measured calibration record and validated configuration path remain required.

7. **Unused planner boundary.** [`RobotManager.__init__()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/robot_manager/robot_manager.py#L20) supports `need_planner: false` on each robot configuration. Otherwise it builds a cuRobo planner with a scene table obstacle. Set this explicit adapter option for joint-only control and disclose it. `CuroboPlanner` is still imported at module scope from `env.planner_manager.curobo_planner`; that module imports the pinned cuRobo runtime, motion planner, inverse-kinematics and type APIs. Installing the pinned dependency or making a separately reviewed lazy-import adaptation remains necessary. Do not substitute scene-aware native EEF IK for the robot-only controller.

8. **Synchronized cameras and payload boundary.** [`ObsManager.render_for_capture()`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/observation_manager/obs_manager.py#L81) calls `wait_for_latest_cameras`; invoke it before reading the current RGB buffers. Deliver head and both wrists at 640×480. [`CameraManager`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/camera_manager/camera_manager.py#L454) exposes `get_camera_intrinsics` and `get_camera_extrinsics`, but optical conventions and projection must be validated. Use explicit allowlisted payload builders; never forward the complete native observation, error, layout, reward or contact dictionary.

## Runtime hazards

- [`BaseEnv`](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/f57e1633ffed59761bc8e568cfe7530c4b33381c/env/environment/base_env.py#L15) defaults to simulation device `cpu` and `use_fabric=False`. Changing the device automatically enables Fabric. Preserve the resolved native configuration rather than silently forcing CUDA physics.
- `create_eval_env` requires a deployment `port` even if the policy client is replaced. Record this as inert configuration and ensure the replacement cannot connect.
- `BaseEnv` imports `isaaclab_tasks.utils.parse_env_cfg`; installing only the smallest IsaacLab source package is insufficient without its needed task/utilities dependency closure.
- The native source imports cuRobo even when planner creation is disabled. The instance's system CUDA toolkit and the pinned PyTorch CUDA 12.8 wheel may differ; inspect any extension build requirements before compiling. Do not change the host driver.
- Upstream `scripts/install.sh` can modify global dependencies and submodule revisions. Exact native/gitlink pins in `configs/source_pins.json` remain authoritative.
- Native result/video directories are relative to the worker's current directory. Give each preparation/attempt an isolated output location and preserve partial evidence on failures.

## Suggested implementation units and pending gates

Candidate units are `native_config.py`, `native_worker.py`, `native_observation.py`, `fragment_executor.py`, and `run_attempt.py`, with separate preparation/calibration commands. Reuse existing approval, lifecycle, IPC and client modules; do not expand policy visibility to simplify integration.

Before requesting full-test approval, complete: procedural camera/image/clean-shutdown pass; pinned native dependencies and asset closure; native layout preview with peak VRAM; measured tool/camera/controller behavior and speed settings; reset reproducibility binding; 300-second physics-paused wait; strict payload/terminal/cleanup validation; and one initial Astra-high planning draft. Present the actual preview, plan, capability differences and concrete one-attempt configuration. Only then request the user's explicit start approval. No live execution smoke, extended continuation, task retry or full test is authorized by this audit.
