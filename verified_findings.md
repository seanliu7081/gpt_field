# P2N-VLA audit: consolidated findings (repo /workspace/ysk/past2next_bug_fixed)

Status legend: VERIFIED = confirmed by two independent adversarial verifiers (code-truth + impact) or by direct
reproduction; REFUTED = a claim the verifiers disproved (do not build on it); PENDING = not yet verified.

## 0. How P2N-VLA is built (verified by reading + tiny-model runs)
- Prefix (VLM): PaliGemma = SigLIP So400m/14 (224 px, 256 tokens/camera, 2 cameras agentview + wrist, 128->224 resize)
  + Gemma-2B (18 layers, width 2048, MQA) over [image tokens | "Task: <LIBERO-10 instruction>, State: <8 bins>;\nAction: "
  right-padded to 96]. State = eef_pos(3) + axis-angle(eef_quat)(3) + gripper_qpos(2), q01/q99-normalized, 256 bins.
  LoRA r16/alpha16 on all 7 projections of all 18 Gemma layers (frozen bf16 base). Weights from lerobot/pi05_base.
- KI block (training only): [KI_BOS, z0..z6] appended after the prompt (causal, sees prefix, never seen by prefix rows);
  KI logits = hidden @ ki_table.rows^T (5000 rows initialised from PaliGemma rows 255999..251000). KI loss = CE on the
  8 OAT tokens of the target chunk. It is the ONLY gradient path into LoRA / ki_table (and SigLIP in vision_action).
- Expert (action head): the pi05_base Gemma-300M expert (18 layers, width 1024), adaRMS folded at c0=time_mlp(sincos(0.6))
  into per-segment modulations (segments RAWDIFF / HIST / AR). Suffix = [9 RAWDIFF tokens (7 past commands + 1st and
  2nd differences, linear projections + type/time embeddings) | (4 HIST tokens, gate variant) | 8 AR tokens
  (BOS, z0..z6)]. RAWDIFF/HIST rows attend only to themselves (static per-token memory); AR row i attends to all valid
  prefix K/V of EVERY Gemma layer (per-layer K/V, pi0 style), valid RAWDIFF keys, HIST keys (+log-gate), AR keys j<=i.
  Prefix K/V are DETACHED (knowledge insulation): the AR loss reaches only the expert, tok_emb and the condition
  projections. Head = tok_emb (5001 x 1024) tied output. Loss = CE_AR + lambda_ki * CE_KI. Deploy: greedy (T=0)
  KV-cached decoding of 8 tokens -> frozen OAT decoder -> 16x7 actions, execute 8.
- Self-past: with p=0.5 (after 1k warmup + 4k ramp) the past-command history of a training window is regenerated by the
  model itself from the previous window (t-8), sampled at T=1/top-10, so training histories resemble deployment
  histories (which are the model's own executed commands).
- Variants: p2n_vla (LoRA scope), vision_action scope (SigLIP+projector trainable by KI CE only; all Gemma incl. LoRA frozen),
  p2n_vla_state_gate (adds 8 measured states -> 4 HIST tokens behind a learned scalar log-gate; NEVER trained beyond a
  2k-update smoke), pi05_ki_flow (same stack with pi05's flow expert; NEVER trained).

## 1. Code correctness (VERIFIED, positive)
No real bug in the forward/backward/decoding paths: prefix/suffix masks and RoPE positions; KI rows invisible to the
expert (bitwise identical expert logits with and without the KI block); cached decoding == teacher forcing (9.5e-7 fp32);
BOS/shift alignment; pad invariance; gradient reachability (CE_AR -> exactly the 'ar' clip group, CE_KI -> exactly 'ki';
every trainable gets a gradient, so DDP find_unused_parameters=False is safe); dtype placement (bf16 VLM, fp32 expert
attention); activation-checkpointing equivalence; self-past window arithmetic; normalizer separation; stateful rollout
protocol; pi05 loader/fold; optimizer and clip partitions; EMA; validation RNG isolation; resume checks; rollout isolation.
Test suite: 232/247 non-asset tests pass; all 15 failures come from one stale config path (B1).

## 3. Design flaws / unproven design choices (VERIFIED)
- C1 lambda_ki is inert for any value > 0. The two losses reach disjoint parameter sets, the workspace clips each set
  separately to max_grad_norm=1.0, and the pre-clip norms exceeded 1 on ~100% of updates (KI min 4.26, p50 16.3; AR p50 7.1).
  So the KI update is g/||g|| regardless of lambda; any lambda_ki >= ~0.24 gives the identical trajectory (reproduced on a
  tiny model). Only lambda_ki=0 (freeze LoRA/KI table) is a real switch. Training effectively runs normalized-gradient AdamW.
- C2 Knowledge insulation in a 450-demo single-domain fine-tune: the action loss never adapts the VLM (0/39 SigLIP
  tensors receive AR gradient). It is the intended, documented, tested pi0.5-KI design, NOT a code bug. But the VLM-side
  signal is weak/overfitting: LoRA run KI train token acc 0.24 at 30k; vision_action KI train acc 0.975 vs val 0.05.
  Literature: KI was designed to protect web knowledge at pretraining scale with full-backbone FAST CE + VLM co-training;
  openpi's own pi05_libero fine-tune (92.4 LIBERO-10) uses no stop-gradient and trains everything with the action loss.
- C3 Pretrained-expert reuse is a faithful fold, but its value for a discrete AR head is untested: the pi05 expert's
  input/output interface is replaced (fresh tok_emb at RMS 0.76, causal AR mask, diagonal-only condition tokens, new RoPE
  offsets); no random-init-expert control exists. Training started sanely (loss_ar = ln 5000), so 'harmful init' is unsupported.
- C4 (PENDING) state-gate: one scalar logsigmoid bias <= 0 on all AR->HIST logits; attenuate-only and possibly not
  identifiable against the expert's own Q/K, so gate_mean is a weak diagnostic.
- C5 Self-past histories are sampled at T=1/top-10 while deployment decodes greedily (T=0); the sibling non-VLA P2N policies
  deploy and self-past at the same temperature. A history-distribution mismatch (design question, low severity).
- C6 History tokens are per-token static memory read only by AR rows; the VLM never sees past commands. VERIFIED as a
  fact but REFUTED as an explanation of the gap: the 0.772 non-VLA P2N uses the same mechanism (per-token MLP memory,
  cross-attended only). Literature agrees history belongs in the head, not the VLM prefix.
- C7 Frozen zero-B LoRA still runs (and is serialized) in vision_action: wasted compute only.
- C8 vision_action trains the 414.8M SigLIP+projector at the 'pretrained' LR 5e-5 (same as the expert), no EMA.

## 4. Methodology problems (VERIFIED unless marked)
- D1 The LoRA run was resumed at update 20k on a rebuilt, re-ordered libero10_N500.zarr (identity c30ea5f3 -> 05dcceae)
  with training.allow_dataset_change=true. The seed-42 split is positional, so ~45 of the 50 post-resume 'validation'
  demos were training demos for 20k updates and the run trained on ~495 distinct demos. Validation after 20k (incl.
  training_summary last_validation) is NOT held-out (val token acc 0.115 -> 0.538 at the resume). SR measurements are
  valid, but the 25k/30k models had extra demos. README's "450 training demos" is wrong for those snapshots.
- D2 (PENDING) The frozen OAT tokenizer was fit on the original zarr's positional train split; on the rebuilt zarr ~45/50
  of the policy's held-out demos were in the tokenizer's training data (provenance check compares strings, not content).
- D3 No controls were ever run: pi05_ki_flow (same-stack flow head), self_past_p=0, lambda_ki=0, random-init expert,
  state-gate VLA. So 0.446 / 0.706 cannot be attributed to the P2N head, KI, self-past or the pi05 init.
- D4 vision_action vs LoRA is confounded: trainable scope + EMA on/off + cosine horizon 30k vs 100k + micro-batch 8x2x2 vs
  1x2x16 + eval parallelism 10 vs 5 envs + val set 3200 vs 400 windows. Matched-step SR: 10k 0.348 vs 0.362 (n.s.),
  20k 0.418 vs 0.556, 30k 0.446 vs 0.652 (McNemar p<1e-4) -- but at 30k the LoRA LR had annealed to 5e-6 while VA was at 4.1e-5.
- D5 Held-out token CE is dissociated from SR: vision_action val CE rises 5.10 -> 7.33 while SR 0.36 -> 0.71 and plateaus;
  val token acc flat 0.09, val recon MSE flat ~0.05 => overconfidence, not worse predictions. CE cannot select checkpoints.
  REFUTED: "official SR is inflated because LIBERO official init states are the demos' init states" -- 0/50 official init
  states match any demo's initial state in every task.
- D6 (PENDING) Official-protocol init states for KITCHEN_SCENE4/6/8 depend on each worker's prior reset count (fixture
  placement written to sim.model is not restored by set_init_state), so 10-env and 5-env evaluations differ on 3 tasks.
- D7 The 0.772 non-VLA baseline is not directly comparable: Past2NextSelfPastPolicy (robomimic ResNet-18 from scratch,
  76x76 crops, 256-d 4-layer cross-attention AR decoder, n_obs_steps=2, deploy T=1/top-10), scored by the LEGACY
  LiberoRunner (autoreset, seeded random inits; the protocol option did not exist yet) and chosen as the best epoch.
- D8 Best-of-snapshot selection on the test schedule (VA best 0.706 @40k vs last 0.678 @70k, n.s.).
- D9 vision_action was stopped at 73.1k of 100k updates (LR 1.27e-5, un-annealed); no training_summary.json.
- D10 Validation caps are batch counts (3,200 vs 400 windows across runs).
- D11 Docs say transformers 5.2.0; runs used 4.57.6.

## 5. Key results (official LIBERO-10 protocol, 500 episodes, 550 steps, greedy)
- p2n_vla (LoRA r16, frozen SigLIP, EMA, 30k): 0.188 (5k) / 0.348 / 0.356 / 0.418 / 0.458 / 0.446 (30k).
- vision_action (SigLIP trainable via KI only, Gemma frozen, no EMA, 100k cosine, stopped 73.1k):
  0.362 (10k) / 0.556 / 0.652 / 0.706 (40k) / 0.674 / 0.704 / 0.678 (70k).
- Per task, LoRA@30k -> VA@70k: stove+moka 0.28->0.76, both moka pots 0.02->0.48, book->caddy 0.10->0.68,
  mug+pudding 0.22->0.52 (all p<=0.008); coarse pick-and-place tasks unchanged (~0.7-0.9).
- Training: LoRA run 12 samples/s after self-past (16 before), ~26 h incl. evals on 2x4090; VA 4.6 samples/s, ~147 h.
