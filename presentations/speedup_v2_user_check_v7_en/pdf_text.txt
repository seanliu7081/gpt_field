ACTION INTERFACE
Three execution paths, different responsibilities
The model selects one action type per decision. Optional payloads not used by that type remain null.
Path
What it executes
What this does not imply
execute
1–6 generic segments; measured completion;
up to 240 control steps per sequence.
No object recognition, grasp certificate or collision-free
path guarantee.
motion
A numerical pose/gripper target for 1–5
control steps.
Target may not be reached within that short grant.
macro
Optional legacy hold, turn, place_on or
release, with its own prerequisites.
A semantic plan intent is not proof that a native macro
implements it.
observe / finish
Fresh observation, or a completion claim
followed by observation.
Neither action sets official success.
v7’s measured acceleration in these tests came from execute fragments; native macro actions were zero.
[M1,M2,M3,M5] Legacy macro grants are bounded and may require calibration / grounding; they are optional.

GENERALITY AND INFORMATION BOUNDARY
What is reusable—and what still requires judgment
Task-independent code does not establish that all tasks or spatial meanings are supported correctly.
Reusable implementation
Five fragments: move_to_pose, move_relative,
approach, set_gripper, wait.
Measured state and explicit handoffs.
No task IDs, object names or predefined task
coordinates in the fragment executor.
Model-selected route, grasp and checkpoints.
Limits of the current interface
Input: RGB, robot pose/gap/joints, camera and
tool geometry, action feedback.
No hidden object poses, depth, contact identities
or goal predicates.
Fragment constraints rely on model
interpretation; there is no whole-arm collision
planner.
Local feedback is proprioceptive. Fresh visual reasoning happens at model decision boundaries.
[M1–M4] Six recent image pairs plus continuous textual execution history. Geometry calibration does not provide object depth.

DESIGN CONCLUSIONS
What to retain, and what to improve next
These are conclusions from the recorded tests, not new changes or validated future performance.
Retain
Model ownership of the full task.
Longer measured fragments where targets are

Explicit gripper stages, checkpoints and
cause-preserving feedback.
Separate task outcome, physical quality and

Next general improvements
Ground directional relations in an explicit frame

Verify whole-object placement from new

Improve contact/cause feedback and route quality.
Evaluate multiple tasks and resets before claiming
